# پالپ ایران — Pulp Iran

وب‌سایت فارسی و راست‌به‌چپِ **توان و تولید سلولز پایتخت** (پالپ ایران): طراحی،
ساخت، نصب و راه‌اندازی خطوط تولید خمیر کاغذ، فلاف پالپ، آلفا سلولز و خمیر از
پسماند کشاورزی و باگاس.

یک سایت **استاتیک** است: بدون build، بدون framework، بدون `package.json`.
سه صفحه (`index.html`, `blogs.html`, `blog.html`)، دو stylesheet، دو فایل JS،
فونت وزیرمتن به‌صورت محلی، و تصاویر در `media/`.

## 🤖 اگر یک agent هستی و این مخزن را تازه import کرده‌ای

**اول این را بخوان، بعد هیچ چیزی را حدس نزن.**

این پروژه در یک sandbox با محدودیت‌هایی نگه داشته می‌شود که **از روی کد قابل
کشف نیستند** و هر کدام یک بار با شکست واقعی کشف شده‌اند. یک دستور همه‌چیز را
برمی‌گرداند:

```sh
sh scripts/restore.sh
```

این کارها را به ترتیب انجام می‌دهد و هر قدم دلیلش را داخل خودش مستند کرده:

| قدم | کار |
|---|---|
| ۱ | گزارش بودجه‌ی حافظه (سقف سختی که کل طراحی را شکل می‌دهد) |
| ۲ | نصب VS Code CLI (اینجا `curl`/`wget` نیست → Python) |
| ۳ | نصب انجین impeccable با **راستی‌آزمایی sha256** (فقط باینری ویندوز در مخزن است) |
| ۴ | نوشتن کانفیگ live-mode |
| ۵ | **کم کردن افزونه‌های VS Code Server از ۳۶ به ۶** — اجباری، نه اختیاری |
| ۶ | بالا آوردن پروکسی same-origin (بدون آن live mode اصلاً کار نمی‌کند) |
| ۷ | boot کردن impeccable live |
| ۸ | دستورالعمل تونل (چون به انسان نیاز دارد، خودکار نیست) |

فقط می‌خواهی وضعیت را ببینی و چیزی را عوض نکنی:

```sh
sh scripts/restore.sh --status
```

### سه چیزی که اگر ندانی، حتماً خراب می‌کنی

1. **سقف حافظه ۱ گیگابایت است.** یک VS Code Server متصل حتی با ۶ افزونه حدود
   ۷۰۰–۷۵۰ MB هزینه دارد. با ۳۶ افزونه به ۸۱۶ MB و ۱۶ پروسه می‌رسد و کل
   کانتینر OOM می‌شود — به‌همراه `bash` و همه‌ی ابزارهای خود agent. بخشی از عدد
   خام `memory.usage_in_bytes` هم page cache است و قابل بازیافت؛ عدد خام را با
   فاجعه اشتباه نگیر.

2. **مسیر workspace پایدارِ agent (`"$ARENA_WORKSPACE"`) یک mount جداست** که در `ls /home`
   ظاهر نمی‌شود و پروسه‌های spawn‌شده نمی‌توانند قابل اتکا در آن **بنویسند**،
   هرچند می‌توانند از آن بخوانند و exec کنند. `cd` به آن گاهی ENOENT می‌گیرد،
   `sed -i` خروجی ۰ می‌دهد ولی فایل را عوض نمی‌کند. پس: همه‌ی state سرویس‌ها در
   `/tmp`، و اسکریپت‌ها از `$PWD` استفاده می‌کنند نه از مسیر مطلق.

3. **live mode به پروکسی نیاز دارد، نه به port forwarding.** فایل `live.js` آدرس
   هلپر را به‌صورت `'http://localhost:' + PORT` در ۱۴ endpoint هاردکد می‌کند. روی
   یک origin از نوع HTTPS devtunnels این دو بار شکست می‌خورد (mixed content، و
   `localhost` ماشین خود کاربر است). هلپر هم `Access-Control-Allow-Origin`
   نمی‌فرستد، پس cross-origin هم ممکن نیست. `scripts/liveproxy.py` هر دو را از یک
   origin سرو می‌کند و `live.js` را در حین سرو بازنویسی می‌کند. **فقط پورت ۸۰۸۰
   را forward کن.**

## توسعه‌ی محلی (بدون sandbox)

خارج از این sandbox همه‌چیز ساده‌تر است — یک سرور استاتیک کافی است:

```sh
python3 -m http.server 8080
# http://localhost:8080/index.html
```

برای live mode هم `liveproxy.py` لازم نیست، چون `localhost:8400` واقعاً در
دسترس مرورگرت است:

```sh
python3 -m http.server 8080 &
.agents/skills/impeccable/scripts/impeccable live
```

## وضعیت فعلی طراحی

- هیروی وبلاگ یک **چیدمان دومرحله‌ای** است: `.hero-lead` مسیر خواندن و
  `.hero-action` ریل اقدام، با یک جداکننده‌ی `border-inline-start` به‌جای ظرف
  تودرتو. اسکن `detect --scope layout` روی آن **۰ finding** می‌دهد.
- `.hero-well` هیچ border/background/padding/سایه‌ای ندارد تا **تنها لایه‌ی عمق**
  در هیرو خودِ input باشد (رفع الگوی `nested-cards`).
- محتوا صادقانه است: ۴ مقاله‌ی نمونه، ۳ دسته‌بندی، **۰ نویسنده‌ی معرفی‌شده**.

⚠️ یک بدهی مستندسازی باز: `.blog-hero h1` مقدار
`font-size: clamp(2rem, 3.2vw, 3.2rem)` دارد. وسط `clamp()` باید یک length با
واحد نسبی باشد، پس `3.2vw` عملاً نادیده گرفته نمی‌شود و تایپوگرافی مقیاسِ
viewport اعمال می‌گردد — همان چیزی که `DESIGN.md` منع کرده. هنوز دست‌نخورده است.
